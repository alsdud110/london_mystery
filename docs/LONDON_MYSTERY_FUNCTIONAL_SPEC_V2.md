# London Mystery — 기능명세서 V2 (Guest-first Online Service)

> **⛔ 폐기된 방향 (2026-10-16):** 사용자 계정·Firebase·클라우드 동기화 방향은 최종 폐기되었다. London Mystery는 **기기당 탐정 1명, 100% 오프라인** 게임이다. 현재 설계는 `docs/OFFLINE_SINGLE_DETECTIVE.md`. 이 문서의 계정·프로필·동기화·보호자 계정 관련 내용은 더 이상 유효하지 않으며 기록으로만 남긴다.

> **문서 상태:** 소스 대조 완료(2026-10-13) · **D3 = B안(게스트 우선 + 선택적 부모 계정 연결) 확정** · 구현 승인 전
> **기준:** 실제 저장소 대조 결과. 부록 A(V1)는 기존 구현 기준선.
> **표기:** `[CURRENT]` 소스에서 확인된 기존 구현 · `[PLANNED]` 신규 개발 예정 · `[DECISION]` 확정 · `[OPEN]` 결정 필요
> **⚠ 정책 변경 (2026-10-13):** 부모 계정 + 자녀 프로필 구조는 폐기하고 **일반 사용자 계정 + 탐정 프로필** 구조로 변경했다. 흐름: 앱 실행 → 로그인/회원가입/게스트 → 탐정 이름·프로필 → Season 1 → 저장·계정 연동. 게스트 플레이는 유지. 이 문서의 "부모/보호자 계정", "자녀 프로필"은 각각 "사용자 계정", "탐정 프로필"로 읽는다. 단, **한국 만 14세 미만 사용자의 개인정보 처리와 법정대리인 동의 의무는 별개로 유효**하며, 동의 절차가 확정되기 전에는 개인정보 클라우드 업로드를 차단한다(이메일 인증 ≠ 법정대리인 동의). 코드 명칭: `AuthService`, `UserSession`, `FirebaseAuthService`, `FakeAuthService`, `ConsentRepository`.

## 1. 명세 적용 원칙

- 기존 게임 기능(`F-*`, 부록 A)은 보존한다. 콘텐츠·정답·힌트 문구·경제 수치는 승인 없이 변경하지 않는다.
- `O-*`는 신규 기능이며 모두 `[PLANNED]`이다. 구현 완료 전까지 구현됨으로 표시하지 않는다.
- 게스트는 계정 없이 동작하는 **로컬 전용 프로필**이다. 계정 프로필과 같은 저장 구조를 쓰되 클라우드 동기화 대상이 아니다.

## 3. O-001 부트스트랩·라우팅

**입력:** 기기 설정(`lm.device.v1`), 프로필 목록(`lm.profiles.v1`), 레거시 키, (Phase 3~) 부모 세션.
**처리 순서:**
1. 프로필 목록이 없고 레거시 키가 있으면 O-005 이전 실행 → 게스트 프로필 생성·활성화.
2. 프로필 목록이 없고 레거시도 없으면: Phase 1에서는 빈 게스트 프로필 생성(현재와 같은 Title → 등록 흐름). Phase 3부터는 언어/지역 → 진입 선택.
3. 활성 프로필의 네임스페이스로 게임 세션(Riverpod 상태·라우터)을 만든다.
4. (Phase 4~) 계정 프로필이면 로컬 상태로 먼저 복원한 뒤 백그라운드 동기화.

**예외:** 이전 중 앱 종료(다음 실행에 처음부터 재시도), 손상된 프로필 목록(레거시·백업에서 복구, 실패 시 새 게스트 + 원본 보존), 인증 만료(로컬 플레이 지속, 동기화만 보류).
**수용:** 재시작 후 같은 프로필 복원, 다른 프로필·계정 데이터 미노출, 무한 리다이렉트 없음, 업데이트 직후 기존 사용자 화면 흐름 동일.

## 4. O-002~003 언어·지역 / 진입 선택

- 언어/지역은 최초 실행 시 선택, 기기 단위 저장. 영어 단서 원문은 번역하지 않는다. 지원 범위 [OPEN].
- 진입 선택 화면: **「게스트로 시작」**(기본, 가입 없음) / **「부모 계정 연결」**. 게스트로 시작해도 나중에 보호자 영역에서 연결할 수 있음을 안내한다.
- 이미 게스트 프로필이 있는 기기(레거시 이전 포함)는 진입 선택을 다시 묻지 않고 Title로 간다.

## 5. O-004~005 게스트 프로필과 레거시 이전

### 5.1 게스트 프로필 [DECISION]
- 계정 없이 현재 기기에서 플레이. Case 진행, Season 해결 기록, XP(`xpRules`), Coin, 힌트 구매 기록을 보존.
- 클라우드 백업·기기 간 복원 없음. 앱 삭제 시 데이터가 사라질 수 있음을 보호자 안내에 표시한다.
- 기기당 게스트 수: 1명 권장 [OPEN].

### 5.2 레거시 이전 [PLANNED]
1. 대상: `lm.progress.v1`, `lm.progress.v1.epNN`, `lm.season.v1`, `lm.wallet.v1`. (`lm.settings.sound`는 기기 설정으로 유지)
2. 새 게스트 프로필 네임스페이스로 **복사** → 디스크에서 다시 읽어 원본과 바이트 단위 비교 → 성공 시 이전 표식 기록.
3. **레거시 원본은 삭제하지 않는다.** 이후 어떤 초기화도 레거시 원본을 건드리지 않는다(삭제 정책 [OPEN]).
4. 이전 표식이 있으면 다시 실행하지 않는다. 표식 기록 전 중단되면 다음 실행에서 대상 네임스페이스를 비우고 처음부터 다시 복사한다.
5. 레거시에 Wallet이 없으면(코인 도입 전 세이브) 해당 프로필에만 1회 소급 지급을 허용한다.
6. 프로필 탐정 이름 = 활성 Case 세이브의 `detectiveName`, 없으면 다른 Case 세이브의 첫 이름.

## 6. O-006~007 동의·부모 인증 [PLANNED]

- 보호자 안내 → 필수/선택 동의 → 동의 기록(버전·시각·보호자 주체) → 가입/로그인. 동의 전에는 계정 생성·클라우드 저장을 하지 않는다.
- 동의 거부·취소 시 게스트 플레이로 돌아간다(게스트 데이터는 그대로).
- 보호자만 인증 자격 증명을 가진다. 자녀에게 이메일/비밀번호를 요구하지 않는다.
- 인증 수단·복구·다중 로그인 정책 [OPEN].

## 7. O-008 자녀 프로필

**속성:** `profileId`(불변, 기기에서 무작위 생성), `kind`(guest / account / operator), `detectiveName`, `createdAt`, `ownerUid`(계정 프로필만), `saveSchemaVersion`. 실명·생년월일은 수집하지 않는다.

**동작:** 프로필 선택 → 해당 네임스페이스로 게임 세션 생성 → 플레이. 전환 시 현재 세션의 저장을 끝내고 세션을 폐기한 뒤 다음 프로필 세션을 만든다. 추가/삭제는 보호자 영역에서만.

**수용:** A/B 프로필이 같은 Case를 완료해도 XP/Coin/힌트/Notebook/배지가 섞이지 않는다. 전환 후 이전 프로필의 상태·화면·라우트·일회성 권한(Parent Report 패스 등)이 남지 않는다.

**탐정 이름 호환:** 프로필의 `detectiveName`이 표시 기준이며, 기존 `GameProgress.detectiveName`도 계속 기록한다(라우터 `hasDetective`, 리포트 등 기존 코드 호환).

## 8. O-009 게스트 → 자녀 프로필 연결 [PLANNED]

1. 보호자 인증 상태에서만 시작. 게스트 기록 요약(해결 Case 수, Coin, XP, 마지막 진행) 미리보기.
2. 대상 선택: **새 자녀 프로필로 연결**(기본 권장) 또는 **기존 자녀 프로필에 합치기**.
3. 기존 프로필에 클라우드 기록이 있으면 양쪽 요약을 나란히 보여주고 선택지 제공: 「클라우드 기록 유지」 / 「합치기」 / 「새 프로필로 연결」. 자동 덮어쓰기 금지.
4. 보호자 최종 확인 → 업로드 → 서버 확인 → 게스트 프로필을 `linked` 상태로 표시.
5. 게스트 로컬 원본은 즉시 삭제하지 않는다. 같은 게스트 기록을 다른 프로필에 다시 연결하려면 경고 후 재확인.
6. 연결은 멱등: 재시도해도 Coin·XP·배지 중복 없음.

## 9. O-010~012 클라우드 저장과 경제 무결성

### 9.1 동기화 대상 (계정 프로필만)

| 범주 | 데이터 | 병합 성격 |
|---|---|---|
| Season | `solvedEpisodeIds` | 단조(합집합) |
| Season | `activeEpisodeId` | 비단조(최신 기기 세션) |
| Case | `GameProgress` 회차 (`runId`, `rev`) | 회차 단위 — §9.3 |
| Wallet | `CoinEntry` (키 = 문서 ID) | 키 기준 1회 생성, 금액 충돌 규칙 |
| 설정 | 사운드 | 기기 단위, 동기화 안 함 |

### 9.2 저장 계약
- 모든 클라우드 기록은 `parentUid/profileId` 아래. 클라이언트가 지정한 부모 ID를 신뢰하지 않는다.
- 로컬 저장이 먼저 완료되고 동기화는 비동기. 상태(저장됨/대기/오류) 표시.
- Wallet은 잔액 업로드가 아니라 항목 단위 생성. 같은 키 재전송은 무시.

### 9.3 Case 회차 규칙 [DECISION 방향]
- 각 Case 세이브에 `runId`(회차 식별자), `runSeq`(Play Again마다 +1), `rev`(저장마다 +1)를 둔다.
- 같은 `runId`: 완료 미션·증거·단어는 합집합, 시도·힌트 수는 최댓값, 시간은 최댓값.
- 다른 `runId`: `runSeq`가 큰 회차가 이긴다 → **Play Again으로 지운 기록이 되살아나지 않는다**. `runSeq`가 같은데 회차가 다르면(두 기기에서 동시에 Play Again) 진행이 많은 쪽을 택하고 다른 쪽은 로컬 백업.

### 9.4 Wallet 규칙
- **같은 키, 다른 금액:** 서버에 먼저 생성된 항목이 기준. 로컬 항목은 서버 값으로 교체하고 차이를 진단 로그에 남긴다. TIP 소유권은 금액과 무관하게 유지된다.
- **중복 소급 방지:** 소급 지급은 레거시 이전 프로필에서 1회만. 계정 프로필은 클라우드 수신이 끝난 뒤 Wallet을 만들고 소급하지 않는다.
- **오프라인 동시 구매로 인한 음수 잔액:** 정책 [OPEN] — 대안 비교는 `ONLINE_ACCOUNT_DESIGN.md` §8.

## 10. O-013~015 보호자 관리·보안·개발 데이터

- 부모 인증 영역: 프로필 추가·전환·삭제, 게스트 연결, Parent Report, 계정 설정·동의 철회.
- 「새 모험 시작」은 현재 프로필에만 적용. 계정 프로필의 초기화는 보호자 인증 필요 [PLANNED].
- Operator Mode·debug/playtest 빌드: 운영 클라우드에 연결하지 않는다(개발 프로젝트/에뮬레이터). Operator 도구로 만든 데이터는 동기화·연결 대상에서 제외(방식 [OPEN]).
- 로그에 탐정 이름·이메일·토큰을 평문으로 남기지 않는다.

## 3. 화면별 상세 명세

### F-001~003. 시작/등록/시즌 오프닝

**진입:** 앱 실행 → 신규/기존 사용자 상태에 따른 Title.  
**신규:** 탐정 이름 등록 → Season Cover → `BEGIN SEASON ONE` → Opening 1~5 → `ACCEPT THE CASE` → Case 01 파일 → `START CASE 01` → Story Intro.  
**기존:** `CONTINUE ADVENTURE`를 통해 저장된 탐험으로 복귀. 새 모험 시작/초기화 시 확인 UI가 존재한다고 보고되었으나 정확한 문구와 파괴적 동작은 코드 확인 필요.  
**검증:** 신규·기존 분기, 키보드 닫기, 뒤로가기, 작은 화면 CTA, 저장된 탐정 이름 반영.

### F-004~005. Investigation Board / Case Files

- Season Board는 사건별 해결 상태와 진행 흐름을 제공한다.
- Case Files는 Case 01/02 등 사건 제목을 보여주고 탭 시 Episode를 펼치는 형태로 설계되었다.
- 잠긴 사건, 열림, 해결 상태의 표시가 필요하다.
- Operator Mode의 사건 접근은 일반 잠금과 별개로 처리된다.
- 사건 잠금 해제의 모든 상세 조건은 소스 확인 필요.

### F-006~008. Story / Map / Mission

**기본 반복:** Story Intro → Map → Mission → Well Done → Story Scene → Map → … → Final Mission.  
**지도:** 현재 위치 `YOU'RE HERE`, 목적지 표시, 하단 `GO TO …` CTA 고정 박스.  
**미션:** 지문/편지/증거/상호작용 → 답변 제출 → 정답 또는 오답 분기.  
**영어:** 정답 선택의 핵심 단서는 영어 지문과 사건 맥락에서 제공되며, 단순 번역/암기 퀴즈를 지양한다.  
**오답:** 맥락형 피드백 및 GET A TIP 진입점 제공.  
**주의:** Case별 퍼즐 형태와 정답 데이터는 `lib/data/mock/season1/episodeNN_mock.dart` 등 실제 소스 기준으로 확인해야 한다.

## 4. F-012. GET A TIP — 확인 Dialog

### 4.1 진입점

1. Mission 화면 `Get a tip`
2. 오답 피드백의 힌트 버튼
3. Final Mission의 힌트 버튼

세 진입점은 동일한 팝업 동작을 사용한다.

### 4.2 UI 구성

| 영역 | 표시 내용 |
|---|---|
| 상단 | `YOUR TOTAL COINS` 및 Coin 아이콘·현재 잔액 |
| 중앙 제목 | `Reveal a tip?` |
| 안내 | 현재 Tip 상태에 따라 무료/유료/소유/잔액 부족 문구 |
| 가격 | `FREE` 또는 `20 Coins` |
| 하단 | `CANCEL` / `REVEAL` 가로 배치 |

**형태:** 화면 중앙의 작은 Dialog. 종이 질감·Navy·Gold·기존 폰트 사용. 큰 Bottom Sheet, TIP 카드 목록, `UNLOCK`, `Back to the puzzle`, 잔액 변화 예측 문구는 사용하지 않는다.

### 4.3 상태별 동작

| 상태 | 가격 | 안내 예시 | REVEAL 동작 |
|---|---|---|---|
| TIP 1 미공개 | FREE | Reveal this clue for free. | Tip 1 공개, 차감 0 |
| TIP 1 공개 / TIP 2 미소유 / 충분한 잔액 | 20 Coins | Use 20 coins to reveal this clue. | 20 Coins 한 번 차감, Tip 2 공개 |
| TIP 2 미소유 / 잔액 부족 | FREE | Your partner helps you for free this time. | 차감 없이 Tip 2 공개 |
| 이미 소유한 Tip 재열람 | FREE | This tip is already yours. Read it again for free. | 무료 재공개 |
| CANCEL 또는 팝업 외부 탭 | — | — | 팝업 닫기, 차감/공개 없음 |

**상태 관리:** 팝업을 열 때 대상 Tip 번호를 고정한다. REVEAL 후 재빌드 중 다음 Tip을 참조하지 않아야 한다. 빠른 중복 탭에도 거래는 한 번만 반영한다. 기존 Hint 1/2 문구 자체는 변경하지 않는다.

### 4.4 수용 기준

- [ ] 세 진입점이 같은 팝업을 연다.
- [ ] 표시 잔액과 Wallet 잔액이 같다.
- [ ] TIP 1 무료, TIP 2 20 Coins, 부족 시 무료 도움이 동작한다.
- [ ] CANCEL·외부 탭은 거래를 만들지 않는다.
- [ ] REVEAL 중복 탭으로 이중 차감하지 않는다.
- [ ] 구매/무료 획득 Tip은 앱 재실행·재플레이 후 무료 재열람된다.
- [ ] 360×640, 390×844, 글자 1.3배에서 내용이 잘리지 않는다.

## 5. F-013~014. Wallet / XP Rules V4

### 5.1 경제 규칙

| 이벤트 | XP | Coins | 비고 |
|---|---:|---:|---|
| 신규 Wallet 시작 | 0 | +20 | 시작 지원금 한 번 |
| 일반 미션 최초 해결 | +30 | +30 | Coin 재지급 없음 |
| Final 최초 해결 | +60 | +60 | Coin 재지급 없음 |
| TIP 1 공개 | 0 | 0 | 무료 |
| TIP 2 구매 | 0 | -20 | 소유 기록 후 재열람 무료 |
| TIP 2 잔액 부족 | 0 | 0 | 무료 도움 |

**XP와 Coin 구분:** XP는 소비되지 않으며 진행 기록 기반으로 계산된다. Coin은 Wallet 거래 내역의 합으로 잔액을 계산한다. `lib/data/models/wallet.dart`, `lib/features/game/wallet_controller.dart`, `app_constants.dart`, `scoring.dart` 등이 보고된 관련 코드다.

### 5.2 거래·저장 규칙

- 미션 보상은 미션당 한 번만 지급한다.
- 이미 완료한 미션을 재플레이해도 Coin을 재지급하지 않는다.
- 같은 Tip 구매를 연속 요청해도 한 번만 차감한다.
- 잔액은 음수가 되지 않는다.
- 지갑 저장 후 힌트가 공개되며, 중간 종료 시 재열람은 무료로 처리된다고 보고되었다.
- 앱 재시작 후 Wallet 및 Tip 소유 상태를 유지한다.
- 전체 초기화 시 Wallet도 새로 생성한다.

### 5.3 기존 세이브 마이그레이션

- Wallet이 없는 기존 세이브는 최초 1회 초기화한다.
- 시작 지원금 20과 이미 완료한 미션의 Coin을 소급 지급한다.
- 기존에 열어본 Tip은 소유 처리하고 재차 과금하지 않는다.
- 과거 XP Rules V3의 100/200 XP는 유지한다.
- 신규 해결과 소급 지급을 구분해 같은 미션의 Coin 중복 지급을 방지한다.
- 기존 배지와 Parent Report 기록을 보존한다.

### 5.4 알려진 제약

- 이전/새 XP 규칙을 걸쳐 완료한 Case는 합계에 서로 다른 단위가 섞일 수 있다.
- 진행 저장 성공 후 Wallet 저장만 유실되는 드문 경우 보상이 누락될 수 있다는 코드 분석 보고가 있다.
- Season 1 경제 시뮬레이션상 TIP 2를 매번 구매해도 Coin이 충분히 남는다. 수치는 현재 유지하기로 결정되었다.

## 6. F-015~016. Final Mission / Case Solved

**조건:** 해당 Case의 마지막 추리 단계 도달.  
**처리:** Final 퍼즐 정답 → 해결 기록 및 보상 처리 → 완료 안내 → Case Solved → Investigation Board 복귀/다음 Case.  
**보상:** 최초 완료 시 +60 XP/+60 Coins; 재플레이의 XP 표시는 실제 회차 합계와 일치해야 하고 Coin은 재지급하지 않는다.  
**검증:** 완료 직후 보상 표시, 재방문 표시 숨김, 잠금 해제/다음 Case 전환, 저장 복원.

## 7. F-017. XP·배지

- Rules V4 일반 30 / Final 60 XP; 기존 완료 기록의 Rules V3 XP는 보존한다.
- 행동 기반 배지로 Second Look, Notebook Explorer, Word Collector 등이 보고되었다.
- 이전 Sharp Eyes / Quick Thinker는 신규 지급 규칙에서 제외됐으나 과거 배지 기록과 설명은 유지한다.
- XP를 Coin처럼 소비하거나 Tip 구매에 직접 사용하지 않는다.

## 8. F-018. Parent Gate / Parent Report

- 보호자용 정보는 어린이 게임 흐름과 구분한다.
- Report는 플레이 시간, 미션 진행, 힌트 사용, 조회한 영어 표현 등 **관찰 가능한 활동**을 표현한다.
- `힌트 N번`은 해당 회차에서 연 횟수 기준으로 보고되었다.
- 실제 영어 능력 향상이나 숙련도를 검증 없이 점수로 단정하지 않는다.
- 향후 광고/결제 접근에는 보호자 확인이 필요하지만 실제 SDK는 없다.

## 9. F-019. Operator Mode

**노출:** Debug 또는 `LM_PLAYTEST` 빌드에서만 제공된다고 보고됨.  
**기능:** 사건 순서와 관계없이 열람·테스트 가능.  
**중요:** 직접 미션을 해결하면 **일반 세이브의 진행 기록, XP 및 Coin 보상이 저장**된다. 별도 테스트 세이브는 없다.  
**Game Master 안내:** `Operator Mode lets you open cases for testing. If you solve missions, your progress and rewards will be saved.`  
**정책:** 현행 A안 유지; 보상 차단이나 저장 구조 분리는 미구현.

| 플레이 시간 | `playMillis`, `missionStartPlayMillis` | 시간 집계 |

Wallet의 실제 저장 키, 데이터 직렬화 형식, 트랜잭션 보장 범위는 소스 확인 필요.

## 11. F-021. 사운드·연출

- 효과음/환경음과 관련한 사운드 자산 등록 및 테스트 작업이 보고되었다.
- `pubspec.yaml`의 개별 오디오 파일 등록 방식이 보고되었다.
- 실제 기기 오디오 품질·볼륨·무음 모드·성능 검증은 별도 필요하다.
- 음악 생성 API 제약으로 음악 루프 확보가 제한되었다는 과거 보고가 있다. 현재 빌드의 최종 음악 구성은 확인 필요.

## 12. F-022. 미래 확장 (미구현)
